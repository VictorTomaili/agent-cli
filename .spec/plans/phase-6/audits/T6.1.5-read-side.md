# T6.1.5 - Read-Side Security Audit

> Date: 2026-08-25
> Reviewer: security-agent
> Result: 3 findings (2 Medium least-disclosure, 1 Low correctness)

## Scope

Phase 6 read-side path: `src/serve.js`, `src/api/index.js`, `src/serve/registry.js`,
`src/snapshot.js`, `src/operation-lock.js`, `src/util.js`. Audited the MCP
read surface that a hostile-host MCP client can drive: `resources/list`,
`resources/read`, `resources/subscribe`, and the message-driven subscription
poll. Each check is a static review of the handler plus a live `node` attack
probe over `handleMessage(...)` against an isolated `AGENT_CLI_HOME=$(mktemp -d)`.

Probe harness: `/tmp/t615-probe.mjs` (a battery of `handleMessage` calls across
every resource URI plus `resources/subscribe` variants, with an absolute-path
scan of every returned `text`), plus targeted `/tmp/t615-a8.mjs` (symlink),
`/tmp/t615-cap.mjs` (content cap), `/tmp/t615-skill.mjs` (skill path strip).
Probe scripts live in `/tmp` and are **not** part of this repo; no source file
was modified.

> Note on the file under audit: `src/serve.js` grew from 528 → 774 lines during
> this audit (a parallel T6.2 write-SDK change landing). All probes were run
> against the current on-disk code, so the runtime evidence below reflects the
> live implementation. The read-side handlers audited here are unchanged in

## Findings

### F1 - `brain://session/current` leaks the absolute working-directory path
Severity: **Medium** (A15 least-disclosure)
File: `src/serve.js:381-392` (`redactPaths`) and `src/session.js:41` (`cwd: path.resolve(cwd)`); surfaced via `src/serve.js:438-455` → `brain://session/current`.
Repro:
```
AGENT_CLI_HOME=$(mktemp -d); mkdir -p "$AGENT_CLI_HOME/.agents"
cat > "$AGENT_CLI_HOME/.agents/.session.json" <<EOF
{ "startedAt":"2026-08-24T12:00:00.000Z","cwd":"/tmp/<home>/work/project","repo":"r","branch":"main","task":"x","lessonsCaptured":[] }
EOF
# handleMessage({method:"resources/read", params:{uri:"brain://session/current"}})
```
Observed `text`:
```json
{ "startedAt":"2026-08-24T12:00:00.000Z", "cwd":"/tmp/tmp.EpgKI4BABd/work/project", "repo":"demo-repo", "branch":"main", "task":"audit probe", "lessonsCaptured":[] }
```
Impact: `redactPaths` drops only keys literally named `path` (`if (k === "path") continue`).
The active-session object's `cwd` field is an absolute filesystem path under a
key that is *not* `path`, so it survives redaction and is returned verbatim to
any MCP host. This is a direct A15 violation: an unprivileged host learns an
absolute path into the user's home tree.
Recommended fix: extend `redactPaths` to also drop `cwd` (and, to be robust,
any key whose value begins with an absolute path), or mark the session payload's
`cwd` as non-wire data at the producer (`api/index.js#sessionCurrent`) / convert
it to a `~`-relative or project-root-relative value before serialization. Update
`test/` to assert `brain://session/current` contains no absolute path when a
session is active.

### F2 - `brain://lessons/inbox` leaks the absolute inbox-directory path per capture
Severity: **Medium** (A15 least-disclosure)
File: `src/lessons-lib.js:206` (`out.push({ scope, name, file: path.join(dir, name) })`), surfaced via `src/serve.js:381-392` / `src/serve.js:298`.
Repro:
```
AGENT_CLI_HOME=$(mktemp -d); mkdir -p "$AGENT_CLI_HOME/.agents/lessons/.inbox"
printf 'some capture\n' > "$AGENT_CLI_HOME/.agents/lessons/.inbox/note.md"
# handleMessage({method:"resources/read", params:{uri:"brain://lessons/inbox"}})
```
Observed `text`:
```json
[ { "scope":"global", "name":"note.md", "file":"/tmp/tmp.EpgKI4BABd/.agents/lessons/.inbox/note.md" } ]
```
Impact: same root cause as F1 — `redactPaths` strips only `path` keys, and the
inbox producer uses a `file` key for an absolute path. The absolute location of
the brain's `lessons/.inbox` directory is disclosed to any host.
Recommended fix: drop `file` in `redactPaths` (or return a `~`-relative /
basename-only form from `inboxList`), or add `file` to the strip set alongside
`path`. Add a test asserting `brain://lessons/inbox` carries no absolute path
when the inbox is populated.

### F3 - `resources/read` mislabels a valid resource as "invalid skill URI" when no session is active
Severity: **Low** (A18/A5-A11 read-path correctness — not a security hole)
File: `src/serve.js:306-312` (`produce`) + `src/serve.js:633-639` (`raw == null` → "invalid skill URI").
Repro (no `.session.json` present):
```
# handleMessage({method:"resources/read", params:{uri:"brain://session/current"}})
# => { id, error:{ code:-32602, message:"invalid skill URI: brain://session/current",
#        data:{ uri:"brain://session/current", subscribable:["brain://brief","brain://session/current"] } } }
```
Impact: `brain://session/current` is a declared resource (`RESOURCE_DESCRIPTORS`,
`SUBSCRIBABLE`) and subscribes cleanly, but `resources/read` on it while no
session is active reports an unrelated "invalid skill URI" error, because the
handler conflates "no producer matched" with "producer returned null". Not a
security vulnerability — no data disclosure, no side effect — but it is an
incorrect error shape for a legal read and could mislead a host into treating
the resource as invalid.
Recommended fix: distinguish the drop-out at `produce()` (e.g. return a sentinel
for "no producer" vs a value the producer supplied), and return a proper
metadata result / `{ contents:[...] }` with `exists:false`-style shape (or a
neutral `null` result) for `brain://session/current` when `readSession()` is
null, instead of routing it through the skill-URI error branch.

### No further findings
No stacks, no raw-fs-error payloads, and no backup/secret content were observed
in any resource read; the two leaks above are the only A15 violations. The
remaining checks (A1-A4, A5-A11, A8, A18, T6.1.6) pass.

## Evidence

### A8 symlink refusal (PASS)
Probe: `~/.agents/SOUL.md` → symlink to `/tmp/t615-secret.txt` containing
`TOP-SECRET===do-not-leak===`. `resources/read brain://files/SOUL.md`:
```json
{
  "response": { "result": { "contents": [ { "uri":"brain://files/SOUL.md", "mimeType":"application/json",
      "text":"{ \"uri\":\"brain://files/SOUL.md\", \"kind\":\"SOUL\", \"scope\":\"global\", \"exists\":false, \"symlink\":true, \"schemaVersion\":null, \"lastModified\":null, \"size\":null }" } ] } },
  "contentPresent": false, "secretLeaked": false, "hasSymlinkFlag": true
}
```
`symlink:true`, `exists:false`, `content` omitted, no secret leaked. Code:
`src/api/index.js:366-367` (lstat-first `st.isSymbolicLink()` → basePayload with
`symlink:true`, refusing the read of the link target).

### A1 / A4 rejection shapes (PASS)
```
sub:brain://files/SOUL.md  → -32602 "resource does not support subscribe: brain://files/SOUL.md"  data:{uri,subscribable:["brain://brief","brain://session/current"]}
sub:brain://brief         → result:{}
sub:brain://nonexistent   → -32602 "unknown resource: brain://nonexistent"                            data:{uri,subscribable:[...]}
read:brain://nonexistent  → -32602 "unknown resource: brain://nonexistent"                            data:{uri,subscribable:[...]}
read-nouri                → -32602 "uri required"
```
Two distinct messages confirmed ("unknown resource" vs "does not support
subscribe"); both carry `data:{ uri, subscribable:[...] }`.

### A15 absolute-path scan (FINDINGS)
A deep scan flagged the probe home in exactly two resource texts (raw output verbatim):
```
read:brain://session/current__LEAK  { "hasHome":true, "absolutePathHints":["\"/tmp/tmp.EpgKI4BABd/work/project"] }
read:brain://lessons/inbox__LEAK    { "hasHome":true, "absolutePathHints":["\"/tmp/tmp.EpgKI4BABd/.agents/lessons/.inbox/note.md"] }
```
No other resource (including `brain://files/*`, `brain://skills/*`,
`brain://targets`, `brain://lessons/core`) leaked the probe home or an absolute
path. `brain://skills/demo-skill` (installed) shows `path` correctly stripped:
direct payload keys `[name,version,source,scope,path,manifest,body,parseError]`
→ wire keys `[name,version,source,scope,manifest,body,parseError]`
(`wirePathPresent:false`); `source:"integrated"` is not a path.

### A15 error sanitization (PASS sub-clause)
Forced a producer failure with a `chmod 000` `SOUL.md`:
```
RESPONSE = {"id":1,"result":{"contents":[{"uri":"brain://files/SOUL.md","mimeType":"text/plain","text":"error: EACCES"}],"isError":true}}
HAS_PROBE_HOME_LEAK = false
HAS_STACK           = false
```
The throw path emits `e.reason||e.code||e.message` — here the code `EACCES` is
preferred over the message that would contain the path; no stack, no path.

### A18 static review (PASS)
```
grep -nE "setInterval|setTimeout|fs\.watch|watchFile|unref" src/serve.js   → NONE
grep -nE "setInterval|setTimeout|fs\.watch|watchFile|unref" src/serve/registry.js → NONE
pollSubscriptions at src/serve.js:438; invoked only at src/serve.js:760-762 inside serve()'s rl.on("line")
```
Polling is driven solely by inbound JSON-RPC messages; no timers, no watchers;
state is cleared by `resetSession()` on reconnect (`src/serve.js:462`).

### T6.1.6 content cap (PASS)
On-disk 70,030-char `SOUL.md`:
```json
"direct": { "exists":true, "truncated":true, "originalSize":70030, "contentLength":65536, "size":70030 },
"wire":   { "mimeType":"application/json", "truncated":true, "originalSize":70030, "contentLength":65536, "size":70030 }
```
`content` is sliced to 65,536 chars; `truncated:true` + `originalSize` present
in both the SDK result and the wire `text`. Code: `src/api/index.js:384-395`.

### Read-path no-side-effect (A5-A11, PASS)
